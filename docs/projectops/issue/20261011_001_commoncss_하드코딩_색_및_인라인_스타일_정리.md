📝 현재 문제점
---

- `common.css` 에 하드코딩된 hex 색이 약 130곳(챗봇 위젯, 버전 배지, 공지, 이슈 헬퍼, 스크롤바 등) 남아 있습니다. 이전 개편에서 수동 다크 오버라이드를 걷어냈기 때문에, 하드코딩 색이 다크모드에서 밝은 색 그대로 보일 위험이 있습니다.
- 템플릿과 JS 일부에 `text-red-500`, `text-blue-500`, `bg-gray-900` 같은 팔레트 색 클래스가 남아 있습니다.
- `dashboard.html`(진행률 바 width)과 `footer.html`(toast z-index)에 인라인 `style=""` 이 있어 프로젝트 CSP 규칙에 어긋납니다.
- 공지 구분점(`·`)의 대비가 2.5 로 낮습니다.

🛠️ 해결 방안 / 제안 기능
---

- 하드코딩 색을 DaisyUI 테마 변수(`--color-primary`, `--color-base-*`, `--color-success` 등) 기반으로 바꿔 라이트와 다크 모두에서 자동으로 맞춰지게 합니다. 의도적으로 고정인 색(Docker 로그 터미널, GitHub 잔디 팔레트, 그림자, 오버레이)은 유지합니다.
- 팔레트 색 클래스는 시맨틱 토큰으로 교체하고, 인라인 스타일은 클래스로 옮깁니다.

⚙️ 작업 내용
---

- `common.css` 하드코딩 색을 속성별(글자, 배경, 테두리)로 구분해 테마 변수로 교체
- 템플릿과 JS 의 팔레트 색 클래스 교체
- 인라인 `style=""` 제거(진행률 바, toast)
- 공지 구분점 대비 보정
- 검증: pro-launch 로 모든 페이지를 라이트/다크, 데스크탑/모바일에서 캡처하고 대비·콘솔 에러·가로 넘침 점검, 챗봇 패널과 모달 등 상호작용 상태 확인
