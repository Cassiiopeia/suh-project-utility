# common.css 하드코딩 색 및 인라인 스타일 정리

## 개요

이전 대시보드 개편에서 수동 다크 오버라이드를 걷어낸 뒤, `common.css` 에 남아 있던 하드코딩 색이 다크모드에서 밝은 색 그대로 보이는 문제가 있었습니다. 대표적으로 챗봇 위젯 패널이 다크모드에서 흰색이었습니다. 하드코딩 색을 DaisyUI 테마 변수로 전환해 라이트와 다크에서 자동으로 맞춰지게 했고, 팔레트 색 클래스와 인라인 스타일도 함께 정리했습니다. 배포 커밋은 `afb4e51` 입니다.

## 변경 사항

### 하드코딩 색 전환
- `static/css/common.css`: 규칙 94개의 hex 와 rgba 색을 속성별로 구분해 테마 변수로 교체(글자는 `base-content`, 배경은 `base-100/200`, 테두리는 `base-300`, 강조는 `primary`, 상태색은 `success/error/warning/info`, 흰 글씨는 `primary-content`). 의도적으로 고정인 색(Docker 로그 터미널, GitHub 잔디 팔레트, 그림자, 오버레이)은 유지
- 공지 구분점 색 대비 보정

### 인라인 스타일 제거
- `templates/fragments/footer.html`: toast 의 `style="z-index"` 를 CSS 규칙으로 이동
- `templates/pages/dashboard.html`: 공지 영역 높이를 클래스로, Task 진행률 바를 `<progress>` 요소로 교체

### 팔레트 색 클래스 교체
- `dashboard.html`, `suhRandom.html`, `static/js/taskTracker.js`: `text-red-500` 등을 `text-error`, `text-primary`, `text-success` 등 시맨틱 토큰으로 교체
- `sejongAuth.html`, `suhRandom.html`: 히어로 버튼을 `btn-neutral`, `btn-primary` 로 교체
- `dashboard.html`: AI 서버 상태의 로딩 문구 대비를 올리고 `removeClass` 대상 클래스를 함께 변경
- `static/css/tailwind.generated.css`: 재생성

## 주요 구현 내용

- 색을 값 단위로 일괄 치환하지 않고 속성에 따라 달리 변환했습니다. 같은 흰색이라도 `color` 이면 `primary-content`(버튼 위 글자), 배경과 테두리이면 `base-100` 으로 바꿔야 다크모드에서 올바르기 때문입니다.
- 변환 대상에서 Docker 로그 터미널과 잔디 팔레트는 제외했습니다. 두 곳은 테마와 무관하게 고정된 색이 의미를 가집니다.

## 검증

- 로컬 실제 앱: 13개 페이지 × 라이트/다크 × 1280px/390px, 총 52회 점검. 대비 실패는 일시적인 "확인중" 문구 1건뿐이었고 해당 문구는 수정. Task·공지 CRUD 와 권한 E2E 9/9 통과
- pro-launch 로 챗봇 패널을 다크/라이트에서 변경 전후로 캡처 비교해 다크모드 회귀 수정 확인, 다크 페이지 8개 시각 확인
- 프로덕션 배포 후: CICD-BLUEGREEN 성공, 헬스체크 200, 챗봇 다크모드 정상, 콘솔 에러 없음

## 주의사항

- 새로 추가하는 색은 `common.css` 에 hex 를 쓰지 말고 `var(--color-*)` 테마 변수를 쓰세요. 안 그러면 다크모드에서 다시 밝은 색이 남습니다.
- `common.css` 에는 `!important` 가 아직 68곳 남아 있습니다. 동작에는 문제가 없었습니다.
- `/ai-server` 는 로컬에서 Ollama 가 없어 `models/pull/status` 가 500 을 반환합니다. 이번 변경과 무관합니다.
