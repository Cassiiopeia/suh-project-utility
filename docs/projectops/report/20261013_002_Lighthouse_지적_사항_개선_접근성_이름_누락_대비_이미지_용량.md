# Lighthouse 지적 사항 개선: 접근성 이름 누락, 대비, 이미지 용량

## 개요

프로덕션 대시보드를 Lighthouse(모바일)로 측정해 지적된 항목을 고쳤습니다. 접근성이 85에서 100으로, 성능이 32에서 56으로 올랐고 SEO와 권장사항은 100을 유지했습니다. 배포 커밋은 `021c834`(접근성·대비·이미지)와 `9f34b43`(로딩 게이트 제거)입니다.

## 점수 변화 (프로덕션, 모바일)

| 항목 | 최초 | 1차 배포 | 2차 배포 |
|---|---|---|---|
| 성능 | 32 | 57 | 56 |
| 접근성 | 85 | 100 | 100 |
| 권장사항 | 100 | 100 | 100 |
| SEO | 100 | 100 | 100 |
| 총 차단 시간 | 1,950ms | 40ms | 0ms |
| LCP | 11.4s | 11.3s | 9.5s |
| 누적 레이아웃 이동 | 0 | 0 | 0 |

## 변경 사항

### 접근성
- `templates/fragments/header.html`: 아이콘만 있는 메뉴·언어 버튼과 다크 모드 토글 두 개에 `aria-label` 추가
- `templates/fragments/footer.html`: GitHub, Instagram, 이메일 링크에 `aria-label` 추가
- `static/css/common.css`: 스크롤 등장 애니메이션이 투명도 0.35에서 시작해, 측정 순간 글자가 흐리게 잡혀 대비 부족 138건의 원인이 되던 문제를 이동만 하도록 변경
- `dashboard.html`, `header.html`, `footer.html`: 보조 텍스트 투명도 `/40`, `/50`, `/60`을 `/70`으로 상향

### 성능
- `static/images`: 표시 크기보다 훨씬 큰 이미지를 축소(파일명 유지). 헤더 로고 333KB→36KB, passQL 로고 140KB→25KB, 프로필 사진 103KB→17KB, 소만사 로고 86KB→21KB, PickerPicker 로고 34KB→11KB, KAIT 로고 23KB→8KB
- `dashboard.html`: 화면 밖 타임라인 로고에 지연 로딩, 프로필 사진에 `fetchpriority="high"`와 크기 지정
- `header.html`: CryptoJS와 marked 스크립트를 `defer`로 변경(함수 안에서만 호출됨을 확인), Pretendard 글꼴 CSS를 렌더링을 막지 않게 로드
- `dashboard.html`: 페이지 전체를 `hidden`으로 시작해 스켈레톤을 보여주다 문서 로딩 후 500ms를 더 기다려 보여주던 구조를 제거하고 콘텐츠를 즉시 표시(각 데이터 영역의 자체 스켈레톤은 유지)

## 주요 구현 내용

- 총 차단 시간이 1,950ms에서 0ms로 줄어든 것이 가장 큰 개선입니다(이미지 축소와 스크립트 정리의 효과).
- 접근성 대비 지적의 대부분은 색 자체가 아니라 등장 애니메이션의 투명도였습니다.

## 검증

- 로컬: 접근성 100, 회귀 감사 52회에서 대비·넘침·콘솔 에러·실패 요청 0건, 권한·CRUD E2E 9/9
- 프로덕션: 배포 후 Lighthouse 2회 재측정으로 위 수치 확인, 남은 SEO·접근성·권장사항 지적 0건

## 주의사항

- **남은 성능 병목은 서버 응답 시간입니다.** 본문이 없는 `/actuator/health`와 `/robots.txt`도 응답까지 약 0.8초가 걸리고 대시보드는 약 1~1.5초입니다. 방문 기록은 이미 비동기이며 애플리케이션이 더하는 지연은 0.2~0.7초 정도라, 나머지는 Cloudflare에서 원본 서버(자택 NAS)까지의 구간 지연으로 보입니다. 코드로 줄이기 어렵고 서버 위치나 Cloudflare 캐시 규칙 같은 인프라 설정이 필요합니다.
- FCP 는 최초 4.6초에서 7.0초로 오히려 늘었습니다. 측정마다 서버 응답이 1~3초로 흔들려 편차가 큰 값이며, 이번 변경으로 렌더링을 막는 요소가 늘어난 것은 없습니다.
- 렌더링을 막는 리소스(Tailwind CSS, 공통 CSS, Font Awesome CSS, jQuery)가 남아 있습니다. jQuery는 인라인 스크립트가 즉시 사용하므로 `defer`로 바꿀 수 없고, Font Awesome은 아이콘 깨짐을 막기 위해 그대로 두었습니다.
